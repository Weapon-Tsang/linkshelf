# Monitoring Runbook

Last updated: 2026-07-15 Asia/Shanghai

## Status

Sprint 28 adds the minimum monitoring baseline for release: privacy-safe
structured operational events on stdout plus manual checks and incident triage.
No hosted monitoring provider is configured in this workspace.

## Event Schema

Events are one-line JSON objects:

```json
{"type":"linkshelf.operational_event","timestamp":"2026-07-15T09:30:00.000Z","level":"info","name":"health.check","outcome":"ok","metadata":{"status":200}}
```

Common fields:

- `type`: always `linkshelf.operational_event`.
- `timestamp`: ISO timestamp generated by the app.
- `level`: `info`, `warn`, or `error`.
- `name`: stable event name.
- `outcome`: stable result string.
- `requestId`: optional request correlation value when a caller provides one.
- `metadata`: shallow safe metadata.

Events emit automatically when `NODE_ENV=production`. For local or staging smoke
tests, set:

```bash
LINKSHELF_MONITORING_STDOUT=1
```

## Critical Events

| Event | Outcomes | Meaning |
| --- | --- | --- |
| `health.check` | `ok`, `error` | Deployment health route can or cannot open the app database runtime. |
| `auth.google.request` | `cross_origin_rejected`, `invalid_form`, `google_configuration_missing`, `production_redirect`, `invalid_development_role`, `admin_entry_rejected`, `development_identity_missing`, `development_login` | Google auth entry route accepted, redirected, or rejected a request. |
| `auth.google.sign_in` | `accepted`, `rejected` | Production Auth.js Google callback mapped or rejected a local user. |
| `affiliate.redirect` | `redirected`, `not_found`, `invalid_destination`, `persistence_failed` | Affiliate redirect path succeeded or failed before redirecting. |

## Manual Checks

Run these after deployment and during incident review:

```bash
curl -fsS http://127.0.0.1:3000/api/health
docker compose logs --since 15m linkshelf | grep linkshelf.operational_event
docker compose logs --since 15m linkshelf | grep '"level":"error"'
```

Auth smoke check:

1. Confirm `NEXTAUTH_URL` matches the deployed HTTPS origin.
2. Start a Google login from `/login`.
3. Confirm `auth.google.request` emits `production_redirect`.
4. Complete Google consent with a provisioned account.
5. Confirm `auth.google.sign_in` emits `accepted`.

Affiliate smoke check:

1. Open a known product redirect path such as `/api/out/product-sony-a7iv`.
2. Confirm a `302` redirect.
3. Confirm `affiliate.redirect` emits `redirected`.

## Alert Thresholds

Until a hosted alerting integration exists, operators should inspect stdout logs
or configure the host log drain to alert on:

- Any `health.check` event with `outcome=error`.
- Any `auth.google.request` event with `outcome=google_configuration_missing`.
- More than 5 `auth.google.sign_in` `rejected` events in 10 minutes after a
  deployment.
- Any `affiliate.redirect` event with `outcome=persistence_failed`.
- More than 10 `affiliate.redirect` `invalid_destination` events in 30 minutes.

## Incident Triage

1. Check `/api/health`.
2. Inspect recent `linkshelf.operational_event` lines.
3. For `health.check:error`, verify `LINKSHELF_DB_PATH`, persistent volume
   mount, and database file permissions.
4. For `google_configuration_missing`, verify `AUTH_SECRET`, `NEXTAUTH_URL`,
   `AUTH_GOOGLE_ID`, and `AUTH_GOOGLE_SECRET`.
5. For `auth.google.sign_in:rejected`, verify the local user is provisioned with
   the correct Google subject and is not soft-deleted.
6. For `affiliate.redirect:persistence_failed`, verify SQLite write access and
   inspect `click_events` constraints.
7. Roll back using `docs/deployment.md` if a new release introduced the failure.

## Privacy Boundaries

Monitoring events must not include:

- OAuth access tokens or ID tokens.
- Cookies or authorization headers.
- Secrets or passwords.
- Raw Google subjects.
- Email addresses.
- Raw query strings, resume URLs, or share codes.

The event helper redacts metadata keys containing secret-like words such as
`secret`, `token`, `cookie`, `authorization`, `password`, `email`, `subject`, or
`code`. Route instrumentation should still pass only coarse status, role,
product ID, beneficiary, and outcome values.

## Future Integration

A later host-specific monitoring pass can route these stdout events into Sentry,
OpenTelemetry, Datadog, Grafana Loki, CloudWatch, or the selected platform log
drain. Preserve the event names and outcomes when adding those integrations so
existing runbooks and tests remain useful.
